# 4G 手环健康数据接入项目：两日组会汇报素材

> 用途：可直接交给 PPT 智能体生成组会汇报。项目中的密码、服务器 IP、SIM 卡号、完整设备 MAC 均不应放入公开演示文稿。

## 1. 项目一句话

将 T10-4G 手环采集的心率、血氧、体温、电量等原始数据，通过 4G + MQTT 接入本地 SQLite 数据库，并提供后台接收、查询、日志和历史记录能力。

## 2. 背景与目标

### 背景

- 手环不是通过 USB 持续传输数据，而是经 4G 主动向服务器上报 JSON。
- 本地宽带没有公网 IPv4，不能直接作为手环服务端。
- 项目只关注健康数据：心率、血氧、体温、电量；不使用信标定位、巡更或打卡业务。

### 目标

1. 建立安全、稳定的“手环 → 云端 → 本地电脑”数据通路。
2. 将手环 JSON 持久化到本地数据库，支持查询最新值、状态与历史记录。
3. 让手环接入代码独立于其他项目，便于维护和后续扩展。
4. 完成实机数据验证，而不仅是模拟消息验证。

## 3. 最终架构

```text
T10-4G 手环
   │  4G / MQTT 发布
   ▼
云端 Mosquitto Broker
   │  MQTT 订阅
   ▼
本地 health 接收器（后台运行）
   │
   ▼
SQLite：health/data/health_band.sqlite3
   │
   ├── ./health          查询最新值
   ├── ./health status   查询最后上报时间
   └── ./health history  查询历史记录
```

### 关键设计选择

- 云服务器只负责公网 MQTT 中转，不保存业务数据库。
- 本地电脑保存健康数据，避免公网暴露本地数据库。
- MQTT 使用两个最小权限账号：手环账号仅可发布，本地接收器账号仅可订阅。
- 通过 MAC 白名单限制只有已登记手环可入库。
- 当前版本独立运行，不依赖小智 GUI；以后如需联动，可读取 SQLite 再新增适配层。

## 4. 两天内完成的工作

### 第一天：协议确认与基础链路搭建

1. 阅读手环规格书与快速使用说明，确认：
   - 支持 TCP、UDP、MQTT、FTP；项目选择 MQTT。
   - 关键上报字段为 `hr`、`spo2`、`temperature`、`battery`、`mac`、`time`。
   - iPhone 的 `RLBeacon Tool` 可完成网络参数配置。
2. 部署云端 Mosquitto Broker：
   - 服务已启动并对外监听 MQTT 端口。
   - 配置匿名访问关闭、账号密码认证、Topic ACL。
3. 构建本地接收与存储原型：
   - JSON 校验、MAC 规范化、去重、SQLite 存储。
   - 最新数据、设备状态、历史数据查询。
4. 用模拟 JSON 完成端到端验证：
   - 发布账号 → 云端 Broker → 本地订阅器 → SQLite。

### 第二天：实机配置、验证与工程化整理

1. 用 iPhone App 写入并回读手环 MQTT 配置。
2. 验证手环真实连接到 Broker，并收到真实体征 JSON。
3. 从 iPhone 获取设备 MAC，与实际 JSON 中的 MAC 一致；随后启用白名单并关闭未登记设备放行。
4. 发现并记录 App 上传间隔单位偏差：
   - App 界面标注“分钟”。
   - 实机固件按同一数值的“秒”执行。
   - 填 `5` 时约每 5 秒上报；填 `30` 时约每 30 秒上报。
   - 当前设为 `30`，实测上报约每 30 秒一次。
5. 将项目从 `py-xiaozhi` 中独立迁移到 `massage/health/`：
   - 接收器、SQLite、查询、部署模板、测试、文档全部集中。
   - 清除旧项目中的重复手环源码、缓存、旧日志和旧数据库。
   - 历史数据已迁移并核对记录数与最后接收时间一致。
6. 实现一键命令行操作：后台启动、查询、看日志、停止服务。
7. 查询时间从 UTC 改为自动显示北京时间，减少日常使用歧义。

## 5. 实机验证结果

### 通信与存储

- 云端 Broker 服务正常。
- 发布账号、订阅账号、Topic ACL 均验证成功。
- 手环已持续发送真实 JSON。
- 本地接收器日志持续出现“已保存手环数据”。
- 本地 SQLite 中已保存数百条真实手环记录。
- 最新数据、历史数据和最后上报时间均可通过命令查询。

### 数据字段示例（脱敏）

```json
{
  "mac": "已脱敏",
  "time": "十六进制 Unix 时间戳",
  "hr": 70,
  "spo2": 98,
  "temperature": 36.5,
  "battery": 30
}
```

### 时间处理

- 数据库内部使用 UTC，保证统一存储标准。
- 命令行显示时自动转为北京时间。
- 设备测量时间与本地接收时间存在数秒级差异，属于采样与网络传输时延范围。

## 6. 关键问题与解决方式

| 问题 | 处理方式 | 当前结论 |
|---|---|---|
| 本地没有公网 IPv4 | 引入云端 MQTT Broker 做中转 | 已解决 |
| 手环配置不能依赖电脑端工具 | 使用 iPhone `RLBeacon Tool` 配置并回读确认 | 已解决 |
| 数据安全 | 账号分权、Topic ACL、MAC 白名单、私有配置不入库 | 已解决基础防护 |
| 时间显示差 8 小时 | 数据库存 UTC，查询层转北京时间 | 已解决 |
| App 标注分钟但实际按秒上报 | 实机对照日志与历史记录，记录固件行为 | 已确认，当前填 30 对应约 30 秒 |
| 部分 `hr` 或 `spo2` 为 0 | 保留原始数据，不把 0 作为医疗判断；建议佩戴贴合、静止后观察 | 待继续评估 |

| 命令 | 功能 |
|---|---|
| `./health start` | 后台启动 MQTT 接收器 |
| `./health` | 查询最新一条手环记录 |
| `./health status` | 查询手环最后上报时间 |

## 9. 局限与后续工作

1. 健康数据仅做原始展示与查询，不能用于医疗诊断。
2. 需要继续评估 `hr=0`、`spo2=0` 的传感器原始上报语义；可增加“最近有效测量值”视图，但不能覆盖原始记录。
3. 规格书尚未确认 MQTT TLS 支持；后续应确认设备是否支持 TLS，并使用更强密码。
4. 可增加：
   - 数据保留周期与自动清理策略；
   - 异常值/长时间离线告警；
   - 数据趋势图与日报；
   - 小智 GUI 或 Web 面板查询适配层。
