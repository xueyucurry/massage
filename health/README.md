# 4G 手环本地接收与查询

> 2026-11-13 续作状态：六项异常规则、GUI 文案、模拟时间轴及六段固定本地语音已接入。固定音频已改为一次性采集并逐字核对的小智原声；运行时只播放文件。新录音仍需现场逐句试听。

本目录独立接收 T10-4G 手环的 MQTT 数据，并保存、查询心率、血氧、体温和电量。它不依赖小智 GUI 或 `py-xiaozhi` 的任何代码。

## 日常命令

首次准备虚拟环境和唯一依赖：

```bash
cd /home/franka/massage/health
./health setup
```

后台启动接收器：

```bash
./health start
```

查询最新值、状态和历史：

```bash
./health
./health status
./health history
```

查看接收日志或停止接收器：

```bash
./health logs
./health stop
./health receiver-status
```

按保留周期清理旧数据（显式执行，示例保留最近 90 天）：

```bash
./health prune --days 90
```

接收器在后台运行；终端和 GUI 都可以关闭。重启电脑后重新执行 `./health start`。

## 数据与安全

- 数据库：`data/health_band.sqlite3`。
- 数据库内部以 UTC 保存时间；`./health`、`./health status` 和 `./health history` 会自动显示北京时间。
- 数据是原始测量值，不用于医疗诊断。
- **上传间隔单位说明**：App 界面标注为“分钟”，但当前手环固件实测按“秒”执行相同数值；例如填 `5` 实际约每 5 秒上报，填 `30` 实际约每 30 秒上报。当前配置值为 `5`。
- MQTT TLS 支持尚未由规格书确认；公网链路应尽快确认是否可启用 TLS，并使用强密码。

## 与其他目录的关系

本目录包含手环接收器、私有配置、数据库、文档和 MQTT 部署模板。`py-xiaozhi` 不包含接收器或 MQTT 凭据；仅保留一个只读 SQLite 展示/查询适配层，不复制手环数据。

唯一外部依赖是运行 `./health setup` 后在本目录生成的 `.venv/`，其中安装 `paho-mqtt`。云端 Mosquitto 服务继续运行在 `141.147.29.128`，其服务器配置不在本工作区。

健康 GUI 模块位于 `health/gui/`，通过只读 SQLite 读取当前选中的手环数据库；默认是真实库 `health/data/health_band.sqlite3`。接收器与 MQTT 部署仍只由本目录维护。小智主界面只加载该独立模块，不承载其存储、趋势或 BMI 逻辑。

迁移前的数据库已在逐条核对记录数和最后接收时间一致后删除；`health/data/health_band.sqlite3` 是当前唯一的真实手环数据存储位置。独立的 `demo_health_band.sqlite3` 仅存模拟样本。

## 小智只读展示、质量提示与隐私

`py-xiaozhi` 通过健康模块的只读 SQLite 视图展示数据；不会订阅 MQTT、写入体征数据库或读取 `health.json` 中的账号密码。

- 推荐组合：手环约每 5 秒上传，GUI 每 3 秒只读刷新一次。主窗口加载 `health/gui/HealthPanel.qml`，显示身高、体重、BMI、心率、血氧、体温和设备电量；原“任务详情”栏保持独立。
- GUI 启动或点击“启动接收”后会开启新的实时显示会话：历史记录不会先显示。收到本次会话首条心率、血氧、体温均有效的数据后才进入“数据正常”状态；SQLite 历史数据不会被删除，仍可用于历史查询。
- **实机等待提示：** 手环虽约每 5 秒上报，但刚开始时可能持续上报心率或血氧 `0`。2026-11-06 的实测中，从 GUI 会话参照 `01:26:19` 到首条三项均有效的数据 `01:28:20.483` 约为 **121.5 秒**；因此每次启动后应预留约 2 分钟等待稳定体征，不能把这段等待直接判为接收器漏收。
- GUI 的健康卡片可直接“启动”或“停止”本机接收器，并显示进程状态；两个按钮仅调用固定的本地 `health start` / `health stop`，不会执行任意终端命令。关闭 GUI 不会停止已启动的接收器。
- 小智 MCP 已提供 `self.health_band.latest`、`self.health_band.history`、`self.health_band.status`、`self.health_band.assess`，用于语音查询最新值、历史数据、上报状态和数据完整性。
- 接收质量提示检查“未收到数据、接收时间无法识别、超过 20 秒无新数据、测量字段缺失”；生理筛查预警另按下节规则显示，不对心率、血氧或腕温作医学诊断。
- 当最新完整体征数据新鲜且手环电量 `<=20%` 时，健康卡片显示橙色“电量偏低”和充电提示；若同时超时或体征不完整，则优先显示数据质量状态。
- 首条完整有效数据到达后，后续心率/血氧/体温为 `0` 或空值时该字段显示 `--`，状态标为“数据待确认”；其余有效字段仍可进入各自趋势，不会清空既有曲线。

### 健康卡片状态

| 状态 | 触发条件 | 界面行为 |
| --- | --- | --- |
| 等待接收 | 本次 GUI 会话尚未收到心率、血氧、体温均非空且有效的首条数据 | 体征与趋势保持 `--` / 等待，不使用旧会话数据 |
| 数据正常 | 最新体征完整有效、在 20 秒内收到，且电量高于 20% | 绿色提示，展示实时数据与有效趋势 |
| 电量偏低 | 最新体征完整有效、在 20 秒内收到，且电量 `<=20%` | 橙色提示“建议及时充电”；体征和趋势仍正常展示 |
| 数据待确认 | 已收到过有效数据，最新一条心率/血氧/体温存在 `<=0`、空值或血氧大于 100%，且未超时 | 无效字段显示 `--`；其他有效字段参与各自趋势，既有曲线保留 |
| 数据超时 | 已进入有效接收状态，但最新一条距当前超过 20 秒 | 橙色提示无新体征数据；保留最后体征与已有趋势以便排障 |

“接收器运行中 / 未运行”是独立的进程状态，并非上述体征质量状态；接收器未运行通常会导致后续停留在“等待接收”或进入“数据超时”。
- 若最新数据有效且有体征预警，健康卡片徽标优先显示橙色“体征提醒”或红色“紧急预警”；下方仍显示具体预警文字。数据超时、待确认或等待接收时，徽标优先说明数据质量问题。
- 趋势从最近 5 分钟内按时间桶取均值，最多绘制最新 12 点。默认每 30 秒一个点；用户可在趋势栏输入 `5–300` 秒并点击“应用”，设置保存在未纳入 Git 的 `data/gui_health_settings.json`。每个可见点均标注数值。
- 身高、体重在健康卡片内嵌输入；保存后计算 BMI 并写入本机私有 `data/body_metrics.json`。新打开 GUI 时不会显示上一会话的个人资料数值；本次手动录入或设备写入后才显示，保存的私有资料不会因此删除。后续测量设备可调用 `health.gui.model.HealthGuiModel.updateBodyMetricsFromDevice(...)` 写入并显示同一份资料。
- BMI 按中国成人标准生成下一次按摩的建议系数：偏瘦 `0.90×`、正常 `1.00×`、超重 `1.05×`、肥胖 `1.10×`。保存本次身高体重或录入测量设备数据后，自动生成一次性力度预设，无需另按确认键。人工输入的力度作为本次基准，随后仍会乘以 BMI 系数；没有人工输入时，基准由既有部位/检测轨迹逻辑解析。运行中的按摩不自动改力，最终仍受机器人既有牛顿范围限制。预设仅存本机私有 `data/bmi_massage_recommendation.json`。
- GUI 显示 BMI 体型分类和下一次按摩的倍率；启动按摩时，小智工具返回消息、按摩运行状态和后台日志均记录已采用的分类、倍率与最终目标力度，便于核验。录入资料本身不启动按摩。
- `health_alert_policy.json` 中的个人阈值仍仅用于手环查询工具的自定义提示；按摩中的 GUI 与主动语音采用下节的统一规则，避免自定义阈值与按摩预警重复播报。
- 手环数值不会自动启动、暂停、停止或恢复机械臂。用户明确说出暂停、停止或急性不适时走现有本地暂停/停止入口；明确回答降低力度后才调用现有实时调力接口。

### 体征预警（2026-11-13）

GUI 只评估本次会话中接收时间不超过 20 秒的新鲜数据。`0`、空值和越界值中断连续计数，字段显示 `--` 和“数据待确认”，不触发生理播报。体征预警与数据质量状态分别显示，血氧趋势不会单独触发预警。

- 心率持续寻找连续 6 条有效读数，首尾不超过 35 秒且最高与最低相差不超过 15 次/分；取中位数锁定本次稳定基线。最近 6 条的中位数相对基线和前一窗口均升高或下降至少 20 次/分时预警。未找到稳定基线会继续寻找。
- 血氧分两档：连续 3 条 `≤94%` 提醒检查佩戴，连续 3 条 `≤88%` 提醒立即复测并尽快就医；两档都要求首尾不超过 30 秒。
- 体温分两档：连续 3 条 `≤35℃` 或 `≥38℃` 时提醒用体温计复测，首尾不超过 30 秒。界面与播报统一称“体温”，播报保留“手环体温读数”以说明测量来源。
- 同时出现多项时只显示和播报最高优先级一项。真实手环来源的低优先级播报间隔至少 180 秒，模拟来源无此冷却；语音交互忙时低优先级播报可能跳过，高优先级可打断现有语音。
- 六句小智原声已预先录在 `health/audio/`，GUI 只把与批准原文完全一致的句子交给现有音频输出流，不向小智发送生成式请求。播报不会自动调节或暂停机械臂。用户明确说出急性不适时，原有本地暂停入口仍生效。

参考：[MedlinePlus 血氧测量](https://medlineplus.gov/lab-tests/pulse-oximetry/)、[MedlinePlus 发热](https://medlineplus.gov/ency/article/001982.htm)、[NHS 低体温](https://www.nhs.uk/conditions/hypothermia/)、[FDA 血氧仪局限](https://www.fda.gov/medical-devices/products-and-medical-procedures/pulse-oximeters)。

## 数据保留与隐私

- 数据库只保存在本机；小智 GUI 不显示设备 MAC，MCP 查询也会自动脱敏 MAC。SIM 卡号从不返回给 GUI 或 MCP。

- 建议先确认合适的保留期限（例如 90 天），并将数据库备份放在受访问控制的位置。
